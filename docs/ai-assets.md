## 2. 试了两种用法，结论不一样

### 2.1 当"精灵素材" —— 效果不行，放弃

思路是把生成的角色图抠背景 → 重采样到像素尺寸 → 量化到工程调色板（`tools/image_to_sprite.py`）。

生成的原图**质量很好**：提灯少女四个姿态，配色、比例、灯的光晕都到位。但转成精灵后：

| 步骤 | 问题 |
|---|---|
| 抠背景 + 下采样到 26px | 手臂与灯笼的连接丢失，关键动作读不出来 |
| 量化到 22 色调色板 | 出现孤立杂点（已加 3×3 中值滤波缓解，但没根治） |
| 放大 5 倍进画面 | 变成一团色块，**比代码手绘版更难辨认** |

**根本原因**：成片素材有三个硬条件——像素级精确、带 alpha、帧间完全一致。文生图三条都做不到。
它擅长的是"一张好看的图"，不是"一套可动画的素材"。

所以这条路只保留为**参考图**（`assets/reference/`），用来校准调色板与比例，不进成片。

### 2.2 当"场景背景板" —— 效果很好，已接入

换成这个用法立刻成立：背景只要"氛围对"，不需要 alpha、不需要逐帧一致，而且文生图在
**构图和配色上远强于几何绘制**。

做法：1024×1024 → 居中裁 16:9 → 缩到 640×360 → 高斯模糊 0.6 → 降饱和 0.55 → 压暗
→ 顶部再压一道。最后两步是为了**给字幕让出对比度**，否则底太花，白字读不清。

接进 `nightpix/scenes.py` 的 `backdrop()`，有背景板就用、没有自动回退到程序化底：

```python
used = backdrop(surf, "sleep_tug")     # 找不到就返回 False, 调用方走回退
if not used:
    surf.blit(ctx.bg_room, (0, 0))
```

**8 张全部生成并接入**：`ceiling_3am` `two_yous` `brake_gauge` `emotion_curve`
`rumination_loop` `feed_glow` `sleep_tug` `dawn`。

效果对比：原来的纯色渐变房间 → 现在有床、枕头、窗、月光、雨痕、日出。
第 7 段"越想睡越睡不着"的改善最明显——背景板里本来就有一张真实的床。

## 3. 顺带修掉的一个真 bug

接入过程中发现：**压暗后的精灵会顶着一个黑方块**。

排查过程（每一步都验过，不是猜）：

1. 怀疑图集 alpha 坏了 → 测：`alpha 取值 [0,255]`，缩放后仍是 `[0,255]` 硬边，四角透明。**排除**
2. 怀疑压暗函数 `tinted()` 写坏 alpha → 测：透明像素数前后都是 188/480。**排除**
3. 怀疑加色光晕层 → 关掉 `glow_at` 对比，影响范围只有 11×11 像素。**排除**
4. **真因**：`pygame.BLEND_RGB_MULT` 虽然名叫"只乘 RGB"，但它会把**目标 alpha 覆盖成源 alpha**
   （源是不透明 Surface，alpha=255），于是精灵周围的透明区被刷成不透明。

修法：乘法前把 alpha 存下来，乘完写回去。

```python
keep = pygame.surfarray.pixels_alpha(s).copy()
s.blit(mul, (0, 0), special_flags=pygame.BLEND_RGB_MULT)
pygame.surfarray.pixels_alpha(s)[:] = keep
```

**这条值得记住**：pygame 里凡是 BLEND_*_MULT 系列，都不保证保留目标 alpha。

## 4. 最终取舍

| 素材 | 方案 | 理由 |
|---|---|---|
| 场景背景 | ✅ 文生图（8 张全部接入） | 氛围强、细节多，不需要 alpha 与帧间一致性 |
| 人物 / 道具精灵 | ❌ 不用文生图，保留代码手绘 | 必须 alpha + 帧间一致 + 像素精确，文生图做不到 |
| 人物参考图 | ✅ 保留 1 张 | 用来校准调色板与剪影比例，并说明来源 |

产物与来源都留档：
- `assets/reference/SOURCE.md` —— 模型、提示词要点、以及"为什么不进成片"
- `assets/backdrops/*.png` —— 8 张背景板（压暗后的成品）
- `assets/reference/backdrops_raw/*.png` —— 原始生成图，便于换参数重做
