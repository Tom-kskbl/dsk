不只放结果，也放中途踩过的坑、被推翻的设计、以及每一版的取舍理由。

## 1. 选题调研

### 1.1 选题标准（按抖音流量规律）

1. **前 3 秒对号入座** —— 观众必须能立刻说"这说的就是我"
2. **机制可演示** —— 抽象概念要能被"演"出来，不能只有口播
3. **结尾可执行** —— 给 2~3 个今天就能做的动作，制造收藏动机
4. **留钩子** —— 结尾埋下一期，制造关注动机

### 1.2 候选与淘汰

| 候选 | 判断 |
|---|---|
| 深夜为什么更容易崩溃 | ✅ 采用。生理机制清晰、可画成曲线、人人有体验 |
| 拖延症的大脑机制 | ✗ 太泛，同类内容饱和 |
| 为什么越累越睡不着 | ✗ 与"深夜效应"高度重叠，合并进本片第 7 段 |
| 多巴胺戒断 | ✗ 不属于本片情绪线 |

### 1.3 实证支撑

片中不是空口说，关键结论都带出处角标：

- 反刍思维与昼夜节律紊乱、皮质醇分泌的关联综述 —— [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0022395625007733)
- 反刍在昼夜类型与抑郁之间的中介作用 —— [Sleep Medicine](https://www.sciencedirect.com/science/article/pii/S1389945722011145)
- 同一人重复做情绪任务，情绪唤醒度随时间上升 —— Murray et al. 2009（片中角标）
- 睡眠剥夺削弱前额叶—杏仁核功能连接（片中角标 `睡眠剥夺 → 前额叶—杏仁核耦合减弱`）
- 蓝光抑制褪黑素、睡眠努力悖论（刺激控制法依据）

> 旁白里凡是有争议空间的说法都做了降级表述，例如不写"深夜一定会崩溃"，
> 而是写"研究者让同一批人白天和深夜做同一套测试，越到深夜，中性的事越容易被读成坏消息"。

## 2. 时长账（旁白驱动画面）

这是整条流水线的核心机制：**画面时长由配音反推**，不是先定时间轴再配音。

实测口径（本机、千问 qwen3-tts-flash、Cherry 音色）：**约 5.1 字/秒**。

```
每段固定开销 = LEAD 1.10s + TAIL 1.80s = 2.90s
8 段 = 23.2s
片名卡 +3.0s        结尾卡 +3.4s
------------------------------------------
固定开销合计 ≈ 29.6s
目标 178s - 29.6s = 148.4s 旁白 → 148.4 × 5.1 ≈ 757 字
```

**第一版文案 650 字 → 成片 159 秒，偏短。**
补写 `curve` 与 `loop` 两段（这两段原本最薄）+93 字 →
**743 字 → 成片 177.1 秒，落在 178±8 秒目标区。**

改文案不用碰任何画面代码：`night_ep.py` 的 `NARRATION` 改字数，
时间轴、字幕分页、配乐段落、音效事件会全部自动重排。

## 3. 视觉设计

### 3.1 色彩决策

全片**只有两种光源**：冷（屏幕/月光）与暖（灯/日出）。
其余颜色都是这两种光的衰减。这样即使画面很暗，观众也能一眼读懂"光从哪来、人什么状态"。

```
夜色   #05070F  #0B1020  #141C33
冷光   #7FA8D8  (屏幕/月亮)
暖光   #F0C97A  (灯/日出)
警示   #E2705E  行动 #8CD6A8
```

### 3.2 被推翻的设计：新形象「提灯的人」

最初计划是"一个纯剪影的小人物，手里提一盏灯，灯的亮度 = 她的情绪"。
实现过程中被数据推翻了三次，最终改成**背影 + 马尾 + 提灯**：

| 版本 | 做法 | 结果 |
|---|---|---|
| v1 背影剪影 | 几何拼骨架，2x 缩放 | 剪影色 (10,13,26) 与夜色 (12,17,32) 几乎同色，**人物被背景吃掉** |
| v2 正面剪影 | 正面站姿，臂/裙分块 | 空白脸产生**恐怖谷**，像人偶；4x 下仍读作"方块人" |
| v3 正面提灯 | 加发丝高光、裙摆受光 | 好转但仍单薄，且灯位置算错跑到头顶 |
| **v4 背影提灯（定稿）** | 背影 + 马尾 + 长裙下缘受光 | ✅ 剪影审美，零恐怖谷风险；灯作为唯一光源带动整个环境明暗 |

**关键教训**：
1. 剪影必须先验证**与背景的明度差**，否则画完才发现"人不见了"
2. 不画脸 ≠ 没表情 —— 背影反而情绪带宽更大
3. 像素角色要**先定骨架表格再填色**，边画边调会导致比例崩坏

定稿过程留档见 `docs/process/design_concepts.png`（三版候选 × 三档灯亮度对照）。

### 3.3 被推翻的设计：光锥

最初用多边形画"手机照出的光锥"。问题：**硬边 + 均匀亮度 = 一块贴纸**。

尝试路径：
1. 多边形 + 加色混合 → 太亮，边缘是直线
2. 降 alpha → 只是变暗的贴纸
3. 5 层递增长度的薄锥叠加 → 有衰减了，但边缘仍是直线
4. ✅ **椭圆光池**（径向光斑 + 非等比拉伸）→ 柔和、无硬边，符合"手机屏照亮一片区域"的物理直觉

`paint.light_cone()` 仍保留（用于灯芯下方的细光束），但主光效全部走 `pool_glow()`。

## 5. 音频链

```
旁白整轨（千问 TTS，按 tag 缓存为 npy，改文案只重合成变化的那几句）
   ↓ 用旁白包络把配乐压低到 65%（ducking，包络 10ms 峰值 + 140ms 平滑）

   ↓
环境声（雨声，0.12 增益）
   ↓
音效（page / chime / pop / confirm，每条字幕一个 chime）
   ↓

   ↓

```

实测（`ffmpeg -af volumedetect`）：`mean_volume -13.5 dB`，`max_volume -0.4 dB`，无削波。

## 6. 踩过的坑

### 6.1 成片 316 MB —— 胶片颗粒把码率拉爆

第一版成片 `bit_rate=14.96 Mbps`，177 秒 → **316 MB**（GitHub 单文件上限 100 MB）。

原因：`NightFX` 每帧重新叠一层随机颗粒，且每帧都换新颗粒。
随机高频噪声是 x264 最难压的东西，等于人为把码率翻了好几倍。

排查过程用了 `tools/bitrate_trial.py`（只渲前 20 秒试码率，避免每次全片重跑）：

| 版本 | CRF | 20 秒片段 | 推算全片 |
|---|---|---|---|
| 原始颗粒（密度 10%、亮度 ±44、每帧换） | 18 | — | **316 MB** |
| 原始颗粒 | 22 | 7.14 MB | 63.3 MB |
| 稍减颗粒 | 23 | — | 62.4 MB |
| 原始颗粒 | 26 | 4.75 MB | 42.1 MB |
| **完全去颗粒** | 20 | 1.05 MB | **9.3 MB** |
| **细颗粒（密度 1.7%、亮度 ±11、每 5 帧换）** | **21** | **3.05 MB** | **27.0 MB** ✅ |

**结论**：颗粒一项占了 85% 的码率。
最终保留密度 1.7%、亮度上限 11、每 5 帧才换一格的**细颗粒** ——
质感上从"噪点"变成"老胶片起雾"，观感更好，码率只涨约 15%。

**可复用的经验**：
1. 暗场视频本身极省码率，**任何逐帧随机噪声都会让码率翻五倍以上**
2. 想保留胶片感，用**低频静态颗粒循环**，不要逐帧新噪声
3. 定 CRF 一定要用片段试算法，别拿整片试

### 6.2 字幕底衬渐变方向反了

`caption_band()` 原本写成自下而上逐渐变实，结果**最需要遮罩的画面底部是透明的**，
白字直接压在人物身上读不清。改成最下方最实、向上淡出。

### 6.3 角色画布高度算错，脚被裁掉

`FH=46` 但骨架最低画到 `y=47`，脚直接画到画面外。
教训：**先把骨架行号列成表格，再写填充代码**，不要边想边写。

### 6.4 CLI 日志捕获管道偶发失败

`python build_night.py | Select-Object -Last N` 偶尔会让子进程写 stdin 管道失败
（`ffmpeg` 收不到完整帧流）。重跑即通，属偶发，非代码缺陷。
正式出片建议直接运行不接管道。

## 7. 复现方式

```powershell
# 1. 依赖（本机 Python 3.14.6）
python -m pip install pygame-ce numpy scipy pillow imageio-ffmpeg requests edge-tts gTTS

# 2. 配置配音密钥（二选一）
#    a) 环境变量：DASHSCOPE_API_KEY / DASHSCOPE_BASE_URL
#    b) .cache/aliyun.json：{"api_key": "...", "base_url": "https://ws-xxx.maas.aliyuncs.com/api/v1"}
#    没有密钥时会自动退到 edge-tts → gTTS → Windows 本地语音

# 3. 关键帧自检（几秒）
python build_night.py --stills

# 4. 看运动、不听配音
python build_night.py --no-tts

# 5. 完整出片（本机约 155 秒）
python build_night.py

# 6. 验收
python tools/night_report.py
```
